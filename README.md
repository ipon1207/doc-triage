# doc-triage

開発プロジェクトの文書を「腐らない形」で扱うための [Claude Code](https://claude.com/claude-code) スキルです。

文書が腐るのは、書きすぎるからではありません。**更新され続けないと嘘になるもの**を書いてしまうからです。このスキルは、その判別と腐らない形への変換を行います。

## できること

| モード | 使う場面 | 成果物 |
| --- | --- | --- |
| A. 決定を記録する | 「X を採用することにした」「この判断を残したい」 | ADR（`docs/adr/NNNN-*.md`） |
| B. 既存文書を診断する | 「この README 大丈夫？」「Wiki が更新されてない」 | どこが腐るかの診断表と直し方 |
| C. 配置を答える | 「これはどこに書けばいい？」 | 置き場所と理由を 1〜2 行 |
| D. リポジトリを調べて方針を出す | 「何から書けばいい？」「文書がほとんどない」 | 最初に書く 3 件と、書かないもの |

どのモードも、次の 3 つの問いで切り分けます。

1. **コードから導出できるか** — できるなら文書にせず、型・スキーマ・テストに語らせる。
2. **現在形か、過去形か** — 「今こうなっている」は腐る。「あの時こう決めた」は腐らない。
3. **1 つの目的だけを担っているか** — 混ざっていたら、中身を直す前に分割する。

判断基準の詳細は [SKILL.md](SKILL.md) を参照してください。

## インストール

リポジトリを Claude Code のスキルディレクトリに clone します。

```sh
# すべてのプロジェクトで使う場合
git clone https://github.com/ipon1207/doc-triage.git ~/.claude/skills/doc-triage

# 特定のプロジェクトだけで使う場合（プロジェクトのルートで実行）
git clone https://github.com/ipon1207/doc-triage.git .claude/skills/doc-triage
```

## 使い方

明示的に呼び出す必要はありません。設計判断・技術選定・README や設計書の話題が出ると、Claude が自動でこのスキルを使います。

```text
> 認証ライブラリ、Auth0 やめて自前実装にした。予算が通らなかったので
> docs/ 以下の文書、腐ってるところがないか見て
> 環境ごとの接続先 URL はどこに書けばいい？
> このリポジトリ、何から文書化すべき？
```

文書化の一般論や考え方を聞いただけでは発動しません。成果物を出すためのスキルとして設計しています。

## 構成

```text
doc-triage/
├── SKILL.md              スキル本体（共通の判断基準、抽象度の 4 レベル、モードの選び方、モード C の手順）
├── references/           該当モードに入ったときだけ読み込まれる詳細手順
│   ├── adr.md            モード A — 決定を記録する
│   ├── diagnose.md       モード B — 既存の文書を診断する
│   └── survey.md         モード D — リポジトリを調べて方針を出す
└── LICENSE
```
