# doc-triage

開発プロジェクトの文書を「腐らない形」で扱うための Claude Code スキル

文書が腐るのは書きすぎるからではなく、**更新され続けないと嘘になるもの**を書いてしまうため

このスキルはその判別と、腐らない形への変換を行う

## できること

| モード | 使う場面 | 成果物 |
| --- | --- | --- |
| A. 決定を記録する | 「X を採用することにした」「この判断を残したい」 | ADR（`docs/adr/NNNN-*.md`） |
| B. 既存文書を診断する | 「この README 大丈夫？」「Wiki が更新されてない」 | どこが腐るかの診断表と直し方 |
| C. 配置を答える | 「これはどこに書けばいい？」 | 置き場所と理由を 1〜2 行 |
| D. リポジトリを調べて方針を出す | 「何から書けばいい？」「文書がほとんどない」 | 最初に書く 3 件と、書かないもの |

どのモードも、次の問いで切り分ける

1. **コードから導出できるか** — できるなら文書にせず、型・スキーマ・テストに語らせる
2. **現在形か、過去形か** — 「今こうなっている」は腐る。「あの時こう決めた」は腐らない
3. **1 つの目的だけを担っているか** — 混ざっていたら中身を直す前に分割する

判断基準の詳細は [SKILL.md](SKILL.md) を参照。

## インストール

リポジトリを Claude Code のスキルディレクトリに置く。

```sh
# 全プロジェクトで使う場合
git clone <このリポジトリのURL> ~/.claude/skills/doc-triage

# 特定のプロジェクトだけで使う場合
git clone <このリポジトリのURL> <プロジェクト>/.claude/skills/doc-triage
```

## 使い方

明示的に呼ぶ必要はない

設計判断・技術選定・README や設計書の話題が出ると、Claude が自動でこのスキルを使う

```PlainText
> 認証ライブラリ、Auth0 やめて自前実装にした。予算が通らなかったので
> docs/ 以下の文書、腐ってるところがないか見て
> 環境ごとの接続先 URL はどこに書けばいい？
> このリポジトリ、何から文書化すべき？
```

文書化の一般論や考え方そのものを聞いただけでは発動しない

成果物を出すためのスキルとして設計している。

## 構成

- `SKILL.md` — スキル本体。共通の判断基準、抽象度の 4 レベル、モードの選び方、モード C の手順
- `references/` — モード A・B・D の詳細手順。該当モードに入ったときだけ読み込まれる
